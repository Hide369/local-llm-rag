## サブエージェントのディスパッチにはマルチエージェントのサポートが必要です

Codex 構成に追加します (`~/.codex/config.toml`):

```toml
[features]
multi_agent = true
```

これにより、スキルが好むマルチエージェント ツールが有効になります。
`dispatching-parallel-agents` そして `subagent-driven-development` 使用。
どのツールを入手できるかは、モデルのマルチエージェントのバージョンによって異なります
プリセットの選択 (現在のプリセットは V2 を実行し、古いプリセットは V1 を実行します)。あなたを信頼してください
このテーブルを含むテーブル上の実際のツール リストは、
同意しません。

- **スポーン:** クリーンなコンテキストを子供たちに提供します
  `spawn_agent {fork_turns: "none"}`;デフォルト `"all"` あなたのをコピーします
  トランスクリプト全体を子にコピーします。 Codex 0.145 以降では、ロール ファイルは
  `~/.codex/agents/` を介して分離されたフォークに接続します `agent_type`。
  全履歴フォークを受け入れる `model` そして `reasoning_effort` オーバーライド
  (のみ `agent_type` そこでは拒否されます) — 分離されたフォークは SDD です

## スポーン時のモデルルーティング

毎 `spawn_agent` あなた自身が問題を抱えている場合も含めて、あなた自身が問題を提起します。
ファンアウトを実行する生成された子 — セット `model` そして `reasoning_effort`
スキルのモデル選択ルールに従って明示的に
実行中。設定 `model` それだけが罠：子供の努力
あなたのモデルではなく、そのモデルのデフォルトに黙ってリセットされます。

人間のパートナーにマシンレベルのバックストップを追加するよう依頼してください。
`~/.codex/config.toml` したがって、すり抜けたスポーンは依然として次のルートに到達します。
セッションのほとんどを黙って継承するのではなく、意図的な階層を作成します。
高価なモデル:

```toml
[agents]
default_subagent_model = "<a mid-tier model from your spawn allowlist>"
default_subagent_reasoning_effort = "medium"
```

## 環境の検出

ワークツリーを作成したりブランチを仕上げたりするスキルは、
続行する前に、読み取り専用 git コマンドを使用して環境を構築します。

```bash
GIT_DIR=$(cd "$(git rev-parse --git-dir)" 2>/dev/null && pwd -P)
GIT_COMMON=$(cd "$(git rev-parse --git-common-dir)" 2>/dev/null && pwd -P)
BRANCH=$(git branch --show-current)
```

- `GIT_DIR != GIT_COMMON` → すでにリンクされたワークツリー内にあります (作成をスキップ)
- `BRANCH` 空→分離された HEAD (サンドボックスからの分岐/プッシュ/PR はできません)

参照 `using-git-worktrees` ステップ0と `finishing-a-development-branch`
各スキルがこれらのシグナルをどのように使用するかについては、ステップ 1 を参照してください。

## コーデックス アプリの仕上げ

サンドボックスがブランチ/プッシュ操作をブロックする場合 (デタッチされた HEAD
外部で管理されるワークツリー)、エージェントはすべての作業をコミットし、
ユーザーはアプリのネイティブ コントロールを使用できます。

- **「ブランチの作成」** — ブランチに名前を付け、アプリ UI 経由でコミット/プッシュ/PR します。
- **「ローカルにハンドオフ」** — 作業をユーザーのローカル チェックアウトに転送します

エージェントは引き続きテストを実行し、ファイルをステージングし、提案されたブランチを出力できます。
ユーザーがコピーする名前、コミットメッセージ、PR の説明。
