## ルール

**応答やアクションの前に、関連するスキルまたは要求されたスキルを呼び出してください** - 質問の明確化、コードベースの探索、ファイルのチェックなど。状況にとってそれが間違っていることが判明した場合は、それを使用する必要はありません。

**計画モードに入る前に:** まだブレインストーミングを行っていない場合は、最初にブレインストーミング スキルを呼び出します。

次に、「[目的]に[スキル]を使用します」とアナウンスし、そのスキルに従ってください。チェックリストがある場合は、項目ごとに ToDo を作成します。

## スキルの優先順位

複数のスキルが適用される場合は、プロセス スキルが最初に適用されます。プロセス スキルがアプローチを設定し、次に実装スキル (フロントエンド設計など) がそれを実行します。ブレーンストーミングと体系的なデバッグは、スーパーパワーの最も一般的なプロセス スキルですが、ルールはどれにも当てはまります。

- 「X を構築しましょう」 → スーパーパワー: 最初にブレーンストーミングを行い、次に実装スキルを学びます。
- 「このバグを修正」→ superpowers:systematic-debugging が最初に、次にドメイン スキルが続きます。

## 赤旗

これらの考えは、「停止」を意味します。あなたは合理化しています。

|感想 |現実 |
|----------|----------|
| 「これは単なる単純な質問です」 |質問はタスクです。スキルを確認します。 |
| 「まず詳細なコンテキストが必要です」 |スキルチェックは質問を明確にする前に行われます。 |
| 「まずコードベースを調べてみましょう」 |スキルは探索方法を教えてくれます。まず確認してください。 |
| 「git/ファイルをすぐに確認できる」 |ファイルには会話のコンテキストがありません。スキルを確認します。 |
| 「まずは情報収集をさせてください」 |スキルは情報を収集する方法を示します。 |
| 「これには正式なスキルは必要ありません」 |スキルが存在する場合は、それを使用します。 |
| 「このスキル覚えてるよ」 |スキルは進化します。現在のバージョンを読み取ります。 |
| 「これはタスクとしてカウントされません」 |アクション＝タスク。スキルを確認します。 |
| 「そのスキルはやりすぎです」 |単純なものが複雑になります。使ってください。 |
| 「最初にこれを 1 つだけやってみます」 |何かをする前に確認してください。 |
| 「これは生産的だと感じます」 |規律のない行動は時間を無駄にします。スキルはこれを防ぎます。 |
| 「それが何を意味するかはわかっています」 |コンセプトを知る≠スキルを使う。それを発動してください。 |
