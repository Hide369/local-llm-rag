# Git ワークツリーの使用

## 概要

作業は隔離されたワークスペースで行われるようにしてください。プラットフォームのネイティブ ワークツリー ツールを優先します。使用可能なネイティブ ツールがない場合にのみ、手動の git ワークツリーにフォールバックします。

**中心原則:** まず既存の分離を検出します。次に、ネイティブ ツールを使用します。その後、git に戻ります。ハーネスと決して争わないでください。

**開始時にアナウンスします:** 「分離されたワークスペースをセットアップするために using-git-worktrees スキルを使用しています。」

## ステップ 0: 既存の分離を検出する

**何かを作成する前に、既に分離されたワークスペースにいるかどうかを確認してください。**

```bash
GIT_DIR=$(cd "$(git rev-parse --git-dir)" 2>/dev/null && pwd -P)
GIT_COMMON=$(cd "$(git rev-parse --git-common-dir)" 2>/dev/null && pwd -P)
BRANCH=$(git branch --show-current)
```

**サブモジュール ガード:** `GIT_DIR != GIT_COMMON` git サブモジュール内でも同様です。 「すでにワークツリー内にある」と結論付ける前に、サブモジュール内にいないことを確認してください。

```bash
# If this returns a path, you're in a submodule, not a worktree — treat as normal repo
git rev-parse --show-superproject-working-tree 2>/dev/null
```

**もし `GIT_DIR != GIT_COMMON` (サブモジュールではありません):** すでにリンクされたワークツリー内にいます。ステップ 2 (プロジェクトのセットアップ) に進みます。別のワークツリーを作成しないでください。

ブランチ状態を含むレポート:
- ブランチ上: 「すでに分離されたワークスペースにあります `<path>` 枝の上 `<name>`。」
- 分離された HEAD: 「すでに分離されたワークスペースにあります」 `<path>` (分離された HEAD、外部管理)。終了時にブランチの作成が必要です。」

**場合 `GIT_DIR == GIT_COMMON` (またはサブモジュール内):** 通常のリポジトリのチェックアウト中です。

ユーザーはすでに指示の中でワークツリーの好みを示していますか?そうでない場合は、ワークツリーを作成する前に同意を求めます。

> 「分離されたワークツリーをセットアップしますか? これにより、現在のブランチが変更から保護されます。」

すでに宣言されている好みを尋ねることなく尊重します。ユーザーが同意を拒否した場合は、そのまま作業を進めてステップ 2 に進みます。

## ステップ 1: 分離されたワークスペースを作成する

** 2 つのメカニズムがあります。この順序でお試しください。**

＃＃＃１ａ．ネイティブ Worktree ツール (推奨)

ユーザーは分離されたワークスペースを要求しました (ステップ 0 の同意)。ワークツリーを作成する方法はすでにありますか?のような名前のツールかもしれません `EnterWorktree`、 `WorktreeCreate`、 `/worktree` コマンド、または `--worktree` フラグ。使用する場合は、それを使用してステップ 2 に進みます。

ネイティブ ツールは、ディレクトリの配置、ブランチの作成、クリーンアップを自動的に処理します。使用する `git worktree add` ネイティブ ツールを使用すると、ハーネスが認識または管理できないファントム状態が作成されます。

使用可能なネイティブ ワークツリー ツールがない場合にのみ、ステップ 1b に進みます。

＃＃＃１ｂ． Git ワークツリー フォールバック

**これは、ステップ 1a が適用されない場合にのみ使用してください** - 使用できるネイティブのワークツリー ツールがありません。 git を使用してワークツリーを手動で作成します。

#### ディレクトリの選択

この優先順位に従ってください。明示的なユーザー設定は、観察されたファイルシステムの状態を常に上回ります。

1. **宣言されたワークツリー ディレクトリの設定に関する指示を確認してください。** ユーザーがすでに指定している場合は、確認せずにそれを使用します。

2. **既存のプロジェクト ローカル ワークツリー ディレクトリを確認します:**
   「」バッシュ
   ls -d .worktrees 2>/dev/null # 優先 (非表示)
   ls -d worktrees 2>/dev/null # 代替案
   「」
   見つかったら、それを使用してください。両方が存在する場合、 `.worktrees` 勝ちます。

3. **他に利用可能なガイダンスがない場合**、デフォルトで `.worktrees/` プロジェクトのルートにあります。

#### 安全性の検証 (プロジェクトのローカル ディレクトリのみ)

**ワークツリーを作成する前に、ディレクトリが無視されていることを確認する必要があります:**

```bash
git check-ignore -q .worktrees 2>/dev/null || git check-ignore -q worktrees 2>/dev/null
```

**無視されない場合:** .gitignore に追加し、変更をコミットしてから続行します。

**重要な理由:** ワークツリーの内容をリポジトリに誤ってコミットすることを防ぎます。

#### ワークツリーを作成する

```bash
# Determine path based on chosen location
path="$LOCATION/$BRANCH_NAME"

git worktree add "$path" -b "$BRANCH_NAME"
cd "$path"
```

**サンドボックス フォールバック:** の場合 `git worktree add` 権限エラー (サンドボックスの拒否) で失敗した場合は、サンドボックスがワークツリーの作成をブロックし、代わりに現在のディレクトリで作業していることをユーザーに伝えます。次に、セットアップとベースライン テストを適切な場所で実行します。

## ステップ 2: プロジェクトのセットアップ

適切なセットアップを自動検出して実行します。

```bash
# Node.js
if [ -f package.json ]; then npm install; fi

# Rust
if [ -f Cargo.toml ]; then cargo build; fi

# Python
if [ -f requirements.txt ]; then pip install -r requirements.txt; fi
if [ -f pyproject.toml ]; then poetry install; fi

# Go
if [ -f go.mod ]; then go mod download; fi
```

## ステップ 3: クリーンなベースラインを確認する

テストを実行して、ワークスペースがクリーンな状態で開始されることを確認します。

```bash
# Use project-appropriate command
npm test / cargo test / pytest / go test ./...
```

**テストが失敗した場合:** 失敗を報告し、続行するか調査するかを尋ねます。

**テストに合格した場合:** レポートの準備ができました。

＃＃＃ 報告

```
Worktree ready at <full-path>
Tests passing (<N> tests, 0 failures)
Ready to implement <feature-name>
```

## 一般的な合理化

|言い訳 |現実 |
|--------|--------|
| 「明らかにワークツリーにいないので、確認する必要はありません」 |ステップ 0 を実行します。ハーネスによって作成された分離とサブモジュールはどちらも目を欺きます。検出コマンドがそれを解決します。 |
| 」`git worktree add` ネイティブ ツールを探すよりも早いです」 | ネイティブ ツール (例: `EnterWorktree`) は、配置、分岐、およびクリーンアップを所有します。これをバイパスするのが最大の間違いです。これにより、ハーネスが認識できない、または管理できないファントム状態が作成されます。 |
| "ワークツリー ディレクトリはすでに無視されています" |走る `git check-ignore`。無視されないワークツリー ディレクトリは、ツリー全体をリポジトリにコミットします。 |
| "任意のディレクトリ名が機能します" |明示的な命令は、既存のプロジェクトのローカル ディレクトリよりも優れています。 `.worktrees/` デフォルト。 |
| 「ワークスペースは新しいです - ベースライン テストは待つことができます」 |ベースラインが汚れていると、その後のすべての失敗が曖昧になります。今すぐテストを実行してください。失敗を乗り越えて前進するのは、人間のパートナーの使命です。 |
