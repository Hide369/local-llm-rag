# スキル設計のための説得原則

## 概要

LLM は人間と同じ説得原則に反応します。この心理を理解することは、より効果的なスキルを設計するのに役立ちます。つまり、操作するのではなく、プレッシャーの下でも重要な実践を確実に実行できるようにするためです。

**研究財団:** Meincke et al. (2025) N=28,000 の AI 会話を使用して 7 つの説得原則をテストしました。説得テクニックにより、遵守率は 2 倍以上になりました (33% → 72%、p < .001)。

## 7 つの原則

### 1. 権限
**内容:** 専門知識、資格情報、または公式情報源を参照します。

**スキルでの仕組み:**
- 命令語: 「しなければならない」、「決して」、「常に」
- 交渉不可のフレーム: 「例外なし」
- 意思決定の疲労と合理化を排除します

**使用する場合:**
- 規律を強制するスキル (TDD、検証要件)
- 安全性を重視した実践
- 確立されたベストプラクティス

**例:**
```markdown
✅ Write code before test? Delete it. Start over. No exceptions.
❌ Consider writing tests first when feasible.
```

### 2. コミットメント
**概要:** 以前の行動、声明、または公的宣言との一貫性。

**スキルでの仕組み:**
- アナウンスが必要：「スキルの使用をアナウンス」
- 明示的な選択を強制する: 「A、B、または C を選択してください」
- 追跡を使用: チェックリストの ToDo を使用する

**使用する場合:**
- スキルが実際に遵守されていることを確認する
- 複数段階のプロセス
- 責任のメカニズム

**例:**
```markdown
✅ When you find a skill, you MUST announce: "I'm using [Skill Name]"
❌ Consider letting your partner know which skill you're using.
```

### 3. 希少性
**概要:** 時間制限または限られた利用可能性による緊急性。

**スキルでの仕組み:**
- 期限付き要件: 「続行する前に」
- 順次依存関係: 「X の直後」
- 先延ばしを防ぐ

**使用する場合:**
- 即時検証要件
- 時間に敏感なワークフロー
・「あとでやろう」を防ぐ

**例:**
```markdown
✅ After completing a task, IMMEDIATELY request code review before proceeding.
❌ You can review code when convenient.
```

### 4. 社会的証明
**概要:** 他の人の行動や、通常と考えられていることに従うこと。

**スキルでの仕組み:**
- 普遍的なパターン: 「毎回」、「常に」
- 故障モード: 「Y のない X = 故障」
- 規範を確立する

**使用する場合:**
- 普遍的な慣行を文書化する
- よくある失敗についての警告
- 基準の強化

**例:**
```markdown
✅ Checklists without todo tracking = steps get skipped. Every time.
❌ Some people find a todo list helpful for checklists.
```

### 5. 団結
**概要:** アイデンティティ、「私たちらしさ」の共有、グループ内への帰属。

**スキルでの仕組み:**
- 共同作業用の言語: 「私たちのコードベース」、「私たちは同僚です」
- 共通の目標: 「私たちは両方とも品質を求めています」

**使用する場合:**
- 共同ワークフロー
- チーム文化の確立
- 非階層的な実践

**例:**
```markdown
✅ We're colleagues working together. I need your honest technical judgment.
❌ You should probably tell me if I'm wrong.
```

### 6. 互恵性
**概要:** 受け取った給付金を返還する義務。

**仕組み:**
- 使用は控えめに - 操作的だと感じる可能性があります
- スキルで必要になることはほとんどありません

**避けるべき場合:**
- ほぼ常に (他の原則がより効果的)

### 7. 好み
**概要:** 好きな人と協力することを好みます。

**仕組み:**
- **コンプライアンスのために使用しないでください**
- 正直なフィードバック文化との衝突
- お調子者を生み出す

**避けるべき場合:**
- 常に規律を遵守するため

## スキルタイプ別の原則の組み合わせ

|スキルタイプ |使用 |避ける |
|-----------|-----|------|
|規律の強化 |権威 + コミットメント + 社会的証明 |好意、互恵性 |
|指導・技術 |適度な権限 + 団結 |重い権威 |
|コラボレーション |団結 + コミットメント |権威、好み |
|参考資料 |透明度のみ |すべての説得 |

## これがうまくいく理由: 心理学

**明確なルールは合理化を減らす:**
- 「あなたはしなければなりません」は決断疲れを取り除きます
- 絶対言語により、「これは例外ですか?」が排除されます。質問
- 明示的な反合理化カウンターは特定の抜け穴を塞ぎます

**実装意図により自動動作が作成されます:**
- トリガーのクリア + 必要なアクション = 自動実行
- 「X のときは Y を行う」は「通常は Y を行う」よりも効果的
- コンプライアンスに関する認知的負荷を軽減します

**LLM は超人間です:**
- これらのパターンを含む人間のテキストについてトレーニング済み
- 権威言語はトレーニング データのコンプライアンスに優先します
- コミットメントシーケンス (ステートメント→アクション) が頻繁にモデル化される
- 社会的証明のパターン (誰もが X を行う) が規範を確立する

## 倫理的使用

**合法:**
- 重要な慣行が遵守されていることを確認する
- 効果的なドキュメントの作成
- 予測可能な障害の防止

**違法:**
- 個人的な利益を目的とした操作
- 誤った緊急性を生み出す
- 罪悪感に基づくコンプライアンス

**テスト:** ユーザーが完全に理解した場合、このテクニックはユーザーの真の利益に役立つでしょうか?

## 研究引用

**Cialdini、R.B. (2021).** *影響: 説得の心理学 (新規および拡張版)* Harper Business。
- 説得の 7 つの原則
- 影響力研究の実証的基盤

**Meincke, L.、Shapiro, D.、Duckworth, A.L.、Mollick, E.、Mollick, L.、Cialdini, R. (2025)。** Call Me A Gerk: AI を説得して不快な要求に従うようにする。ペンシルベニア大学。
- N=28,000 LLM 会話で 7 原則をテスト
- 説得テクニックによりコンプライアンスが 33% → 72% 増加
- 権威、コミットメント、希少性が最も効果的
- LLM の行動の超人間モデルを検証します

## クイックリファレンス

スキルを設計するときは、次の点を考慮してください。

1. **それはどのようなタイプですか?** (規律 vs 指導 vs 参照)
2. **どのような行動を変えようとしているのでしょうか?**
3. **どの原則が適用されますか?** (通常は権限 + 規律への取り組み)
4. **組み合わせすぎていませんか?** (7 つすべてを使用しないでください)
5. **これは倫理的ですか?** (ユーザーの真の利益にかなうものですか?)
