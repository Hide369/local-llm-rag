# push を契機とした資料の自動ベクトル化（GitLab CI）実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ローカル GitLab の `root/source-archive` へ push された時点で、GitLab CI が
自動的に `local_llm/chroma_db` のベクトルデータを最新の資料と一致させる。

**Architecture:** Windows ホストに shell executor の gitlab-runner を登録する。
`source-archive` リポジトリの `.gitlab-ci.yml` が、Runner のチェックアウト
（`$env:CI_PROJECT_DIR`）を入力として `local_llm/scripts/ci_ingest.ps1` を呼ぶ。
`ci_ingest.ps1` は重い処理の前にすべての失敗条件（入力ディレクトリの正当性、
Streamlit の稼働、venv の存在）を確認してから、既存の `ingest_source.py` を
`--source-dir` 付きで実行する。Runner は GitLab と同じく常駐させず
`run_gitlab.ps1` から起動・停止する。

**Tech Stack:** GitLab CE 19.3.1（Docker、`localhost:8929`）、gitlab-runner
（shell executor、Windows PowerShell 5.1）、Python 3.13（`myvenv313`）、
chromadb 1.0.16、Ollama（`.env` の `OLLAMA_HOST`）

**Spec:** `docs/superpowers/specs/2026-09-05-ci-ingest-design.md`

## Global Constraints

以下は全タスクに共通で適用される。設計書から逐語的に引き写している。

- **`chroma_db` に書き込むプロセスは常に 1 つだけ。** Runner は `concurrent = 1`、
  かつ Streamlit 稼働中は ingest を実行しない（設計書 4.6、5 節）。
- **リポジトリに絶対パスを書かない。** local_llm の場所は Runner の `config.toml` の
  `environment` で `LOCAL_LLM_DIR` として渡す（設計書 4.3）。
- **`.gitlab-ci.yml` の `script` 内で CI 変数は `$env:NAME` と書く。** `rules` の
  `if` は GitLab が評価するので `$CI_COMMIT_BRANCH` と書く。この 2 記法の混在は
  正しい（設計書 4.3）。
- **`--with-vlm` は CI では使わない**（設計書 4.4）。
- **秘密情報を追跡しない。** `infra/runner/config.toml` は登録トークンを含むため
  `.gitignore` に追加する。トークンの値はコミット・ドキュメント・会話ログの
  いずれにも書かない（設計書 6.1）。
- **`local_llm/source` は CI の経路から外れる。** ジョブがこのディレクトリを
  読み書きすることは一切ない（設計書 3.4、4.8）。
- **実測値のみを記録する。** 目安値や「約 N 分程度」といった推測をドキュメントに
  書かない（設計書 8.2、`docs/gitlab-local.md` の方針）。
- **作業ブランチは `feat/ci-ingest`。** `master` へ直接コミットしない。設計書は
  このブランチの `7fbf63f` で既にコミット済み。

### Task 1: `ci_ingest.ps1` の入力検証とガード

CI から呼ばれる入口スクリプトのうち、**Embedding を始める前に失敗すべき条件**を

**Files:**

**Interfaces:**

- Produces: `scripts\ci_ingest.ps1 -SourceDir <path>`。終了コード 0 は
  「すべての事前条件を満たした」、1 は「事前条件を満たさない」。
  Task 2 がこのファイルの末尾に ingest 実行を追加する。

- [ ] **Step 1: 検証スクリプトを書く（失敗することの確認用）**

`scripts/ci_ingest.ps1` はまだ存在しないので、まず検証手順を用意する。
以下を `verify-task1.ps1` としてスクラッチ領域に作る（**リポジトリにはコミットしない**）。

```powershell
# Task 1 の受け入れ確認。4つのケースをすべて確認する。
$ErrorActionPreference = "Continue"
$ciIngest = Join-Path $PSScriptRoot "..\scripts\ci_ingest.ps1"
$results = @()

function Check($name, $expectedCode, $expectedText, $body) {
    $output = & $body 2>&1 | Out-String
    $code = $LASTEXITCODE
    $found = $output -match [regex]::Escape($expectedText)
    $script:results += [pscustomobject]@{
        Case = $name; Expected = $expectedCode; Actual = $code
        TextFound = $found; Pass = (($code -eq $expectedCode) -and $found)
    }
}

# ケースA: 存在しないディレクトリ
Check "存在しないディレクトリ" 1 "ディレクトリがありません" {
    powershell -File $ciIngest -SourceDir "Z:\no\such\dir"
}

# ケースB: 存在するがgitリポジトリでない（DB全消し事故の防止。設計書4.4.1）
$plain = Join-Path $env:TEMP "ci-ingest-plain"
New-Item -ItemType Directory -Force -Path $plain | Out-Null
Check "gitリポジトリでない" 1 "資料リポジトリのチェックアウトではありません" {
    powershell -File $ciIngest -SourceDir $plain
}

# ケースC: source-archive のチェックアウトだが Streamlit が稼働中
# 本物のStreamlitを起動する必要はない。ガードはポートの待ち受けしか見ないため、
# ダミーのTCPリスナーで同じ状況を作れる。
$listener = [System.Net.Sockets.TcpListener]::new([System.Net.IPAddress]::Loopback, 8501)
$listener.Start()
Check "Streamlit稼働中" 1 "Streamlitが起動しています" {
    powershell -File $ciIngest -SourceDir $env:SOURCE_ARCHIVE_DIR
}
$listener.Stop()

# ケースD: すべての事前条件を満たす
Check "正常系" 0 "事前条件をすべて満たしました" {
    powershell -File $ciIngest -SourceDir $env:SOURCE_ARCHIVE_DIR
}

$results | Format-Table -AutoSize
if ($results | Where-Object { -not $_.Pass }) { Write-Host "FAIL"; exit 1 }
Write-Host "ALL PASS"
```

ケースC/D で使う `$env:SOURCE_ARCHIVE_DIR` は、実行前に資料リポジトリの
クローンのパスを入れておく。**`local_llm/source` を指定してよい**（remote 名が
`gitlab` でも設計書 4.4.1 のとおり通る）。

- [ ] **Step 3: `scripts/ci_ingest.ps1` を実装する**

```powershell
# GitLab CI から呼ばれる、資料取り込みの入口。
#
# 設計の根拠は docs/superpowers/specs/2026-09-05-ci-ingest-design.md を参照。
#
# 重い処理の前に失敗条件をすべて確認する順序になっている。全量の取り込みは
# 24分かかるため、20分走ってから「Streamlitが起動していました」と言われても遅い。

param(
    [Parameter(Mandatory = $true)]
    [string]$SourceDir
)

$ErrorActionPreference = "Stop"
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8

# --- 1. 入力ディレクトリの存在 ---
if (-not (Test-Path -Path $SourceDir -PathType Container)) {
    Write-Host "ディレクトリがありません: $SourceDir"
    exit 1
}

# --- 2. 入力が資料リポジトリのチェックアウトであることの確認 ---
# ingest_source.py は入力ディレクトリに無い資料をDBから削除する（孤児削除）。
# これは「入力がリポジトリ全体である」ことが前提の挙動であり、小さなディレクトリを
# 誤って渡すとDBの中身がほぼ全部消える。復旧は全量24分の再取り込みになる。
# CIの正常経路は常に $CI_PROJECT_DIR を渡すので事故は起きない。危険なのは
# 人間が手で叩くときで、動作確認手順がまさにそれを要求している以上、塞いでおく。
#
# remote名は origin とは限らない（local_llm/source の remote名は gitlab）。
# 手動実行でそのディレクトリを渡す経路も残すため、remote名では絞らず
# 全remoteのURLを見る。
$remotes = git -C $SourceDir remote -v 2>$null
if ($LASTEXITCODE -ne 0 -or -not ($remotes -match "source-archive")) {
    Write-Host "資料リポジトリのチェックアウトではありません: $SourceDir"
    Write-Host "  source-archive を指すremoteが見つかりません。誤ったディレクトリを"
    Write-Host "  取り込むとベクトルDBの資料がすべて孤児として削除されるため中止します。"
    exit 1
}

# --- 3. Streamlit 稼働ガード ---
# rag_chat_app.py は PersistentClient を @st.cache_resource でプロセス内に保持し、
# BM25インデックスも起動時に一度だけ構築する。稼働中に別プロセスがchroma_dbへ
# 書き込むと、HNSWファイルの整合が取れなくなる上、更新もアプリ再起動まで反映
# されない。
#
# 既定を8501だけにしてはいけない。過去に8503で起動した実績がある
# （.superpowers/sdd/2026-08-12-markdown-ingestion/streamlit-8503.log）。
$portSpec = if ($env:STREAMLIT_PORTS) { $env:STREAMLIT_PORTS } else { "8501,8503" }
$ports = $portSpec -split "," | ForEach-Object { [int]$_.Trim() }

# 待ち受けが1つも無いとき Get-NetTCPConnection はエラーを投げる。
# $listening が空になるのが正常系なので、エラーは握らず黙らせる。
$listening = Get-NetTCPConnection -State Listen -LocalPort $ports -ErrorAction SilentlyContinue
if ($listening) {
    $busy = ($listening | ForEach-Object { $_.LocalPort } | Sort-Object -Unique) -join ", "
    Write-Host "Streamlitが起動しています（ポート $busy）。"
    Write-Host "  稼働中にchroma_dbへ書き込むとインデックスが壊れるため中止します。"
    Write-Host "  アプリを停止してからジョブを再実行してください。"
    Write-Host "  別用途のポートであれば STREAMLIT_PORTS で監視対象を変更できます。"
    exit 1
}

# --- 4. venv の Python ---
# Activate.ps1 は呼ばない。実行ポリシーの影響を受け、Runnerのコンテキストでは
# 対話シェルと異なる挙動になりうる。インタプリタを直接指定すれば有効化は不要で、
# 失敗する余地が1つ減る。
$repoRoot = Split-Path -Parent $PSScriptRoot
$python = Join-Path $repoRoot "myvenv313\Scripts\python.exe"
if (-not (Test-Path -Path $python -PathType Leaf)) {
    Write-Host "仮想環境のPythonがありません: $python"
    exit 1
}

Write-Host "事前条件をすべて満たしました。"
exit 0
```

- [ ] **Step 1: 検証スクリプトを書く**

`verify-task2.ps1` をスクラッチ領域に作る（**コミットしない**）。

**このタスクの検証は本番の `chroma_db` に書き込む。** 入力には必ず資料リポジトリの
完全なクローンを渡すこと。部分的なディレクトリを渡してはいけない。

```powershell
$ErrorActionPreference = "Continue"
$script = Join-Path $PSScriptRoot "..\scripts\ci_ingest.ps1"

# 実行前のチャンク総数を記録する。取り込み後にこれと比較して、
# 「全消し」が起きていないことを確かめる。
$countBefore = & "$PSScriptRoot\..\myvenv313\Scripts\python.exe" -c @"
import chromadb
from ingest.store import open_collection
print(open_collection(chromadb.PersistentClient(path='chroma_db')).count())
"@
Write-Host "実行前のチャンク数: $countBefore"

$started = Get-Date
powershell -File $script -SourceDir $env:SOURCE_ARCHIVE_DIR
$code = $LASTEXITCODE
$elapsed = [int]((Get-Date) - $started).TotalSeconds

$countAfter = & "$PSScriptRoot\..\myvenv313\Scripts\python.exe" -c @"
import chromadb
from ingest.store import open_collection
print(open_collection(chromadb.PersistentClient(path='chroma_db')).count())
"@

Write-Host "終了コード: $code / 所要: ${elapsed}秒"
Write-Host "実行後のチャンク数: $countAfter"
if ($code -ne 0) { Write-Host "FAIL: 終了コードが0ではありません"; exit 1 }
if ([int]$countAfter -lt ([int]$countBefore * 0.5)) {
    Write-Host "FAIL: チャンク数が半減以上しています。孤児削除が誤作動した疑い"; exit 1
}
Write-Host "PASS"
```

実行は `local_llm` をカレントディレクトリにして行う（`chroma_db` を相対パスで
開いているため）。

- [ ] **Step 3: ingest 実行を実装する**

`scripts/ci_ingest.ps1` の末尾 2 行（`Write-Host "事前条件をすべて満たしました。"` と
`exit 0`）を次で置き換える。

**この置き換えにより Task 1 の `verify-task1.ps1` のケースD は以後合格しなくなる**
（そのメッセージが消え、代わりに ingest が走るため）。ケースA〜C は引き続き

```powershell
# --- 5. 取り込みの実行 ---
# .env の読み込みと Ollama の疎通確認は ingest_source.py 自身が行う
# （load_dotenv と check_ollama）。ここで重ねて確認すると、同じ処理が2か所に
# 分かれて片方だけが更新される。
#
# --with-vlm は付けない。VLMによる画像説明は取り込みが大幅に遅くなるため、
# 無人実行のジョブには載せない。必要なときは手動CLIで実行する。
Write-Host "取り込みを開始します: $SourceDir"
& $python (Join-Path $PSScriptRoot "ingest_source.py") --source-dir $SourceDir
$ingestExit = $LASTEXITCODE

if ($ingestExit -ne 0) {
    Write-Host ""
    Write-Host "取り込みに失敗しました（終了コード $ingestExit）。"
    Write-Host "  差分判定はファイル内容のハッシュで行われるため、このジョブを"
    Write-Host "  そのまま再実行しても成功済みの資料は再処理されません。"
}
exit $ingestExit
```

`ingest_source.py` は `import ingest` を行うため、リポジトリルートが `sys.path` に
必要になる。CLI として直接実行する既存の使い方と同じなので追加の設定は要らないが、
**カレントディレクトリがリポジトリルートであることに依存する**。Task 5 の
`.gitlab-ci.yml` は Runner のビルドディレクトリで動くため、ここで明示的に
移動する必要がある。次のステップで確認する。

- [ ] **Step 3: gitlab-runner をインストールする**

**バージョンを固定する**（`latest` を使わない。理由は Phase 1 設計書と同じ）。
GitLab 本体は 19.3.1 なので、同じマイナーバージョン系列の Runner を選ぶ。
バイナリは次の URL 形式で、`latest` の部分をバージョンに置き換えて取得する。

```
https://gitlab-runner-downloads.s3.amazonaws.com/v<バージョン>/binaries/gitlab-runner-windows-amd64.exe
```

インストール先（例: `C:\GitLab-Runner\`）に配置し、バージョンを確認する。

Run: `C:\GitLab-Runner\gitlab-runner.exe --version`
Expected: 意図したバージョンが表示される。

続いてサービスとして登録する。

```powershell
C:\GitLab-Runner\gitlab-runner.exe install
sc.exe config gitlab-runner start= demand
```

**`start= demand` を省略しないこと。** `install` の既定は自動起動であり、
そのままだと「GitLab は必要なときだけ起動する」方針（設計書 2.3 節）と衝突し、
GitLab 停止中に接続失敗をポーリングし続けてログを汚す。

Run: `sc.exe qc gitlab-runner`
Expected: `START_TYPE` が `DEMAND_START` になっている。

採用したバージョンとインストール先を控える。Task 6 に書く。

- [ ] **Step 1: Runner の状態を返す関数を追加する**

`Get-GitLabHealth` 関数の直後（`run_gitlab.ps1:40` の後）に追加する。

```powershell
function Get-RunnerRunning {
    # Runnerはホスト上のプロセス（コンテナではない）。サービス登録の有無で
    # 確認方法が変わるため、プロセスの存在で統一して見る。
    $process = Get-Process -Name "gitlab-runner" -ErrorAction SilentlyContinue
    return [bool]$process
}
```

- [ ] **Step 2: `up` の末尾に Runner の起動を追加する**

`run_gitlab.ps1` の `"up"` ブロックの最終行

```powershell

        # 先に起動すると、Runnerは接続できないGitLabをポーリングし続けて
        # ログにエラーを書く。
        if (Get-RunnerRunning) {
            Write-Host "Runnerは既に起動しています。"
```

```powershell
        # ジョブが中途半端な状態で打ち切られる。
```
