# ナビゲーション用スライドを取り込み時に落とす

2026-09-06

## 1. 問題

目次・章扉・締めのスライドが検索の上位を占める。中身が無いのに短くキーワード
密度が高いため、BM25 がこれを好む。

`feat/fold-duplicate-chunks` の設計書7節で範囲外とし、別ブランチで設計すると
決めたものである。重複の畳み込みでは解決しないことは実測済みで、回帰ケース
「ファインチューニングについて教えてほしい」は畳み込み後も上位3件が次のとおり
だった。

```
1. 転移学習とファインチューニング   ← 章扉（本文なし）
2. 事前質問への回答 [出典7件]      ← 章扉（本文なし）
3. － 目次 －                      ← 目次スライド
```

3件とも中身のないナビゲーション用スライドである。

### 1.1 実データの規模

現行コーパス（608出現 / 本文538種）に対する実測。

| 種類 | 出現 | 本文 | 例 |
| --- | --- | --- | --- |
| 章扉 | 24 | 18種 | `3\n転移学習とファインチューニング` |
| 目次 | 7 | 7種 | `－ 目次 ー\nRAGの基礎知識\n1\n…` |
| 締め | 7 | 1種 | `ご清聴ありがとうございました\nAIとともに、新しい働き方を始めよう` |
| **合計** | **38** | **26種** | |

すべてセミナー資料7本の PPTX 内にある。締めスライドは7資料が共有しており、
1つの本文に7つの出現がぶら下がる。

**実測との差（2026-09-07）。** 取り込み時の除外は「ナビゲーション除外: 40件」と
表示された。上表の38件とは2件ずれている。これは数える単位の違いである。上表は
DB上のチャンク（分割後）を数え、取り込みの表示は `ParsedUnit`（分割前・チャンク
分割の前段階の単位）を数えている。落とした結果の件数は予測どおり
608−38=570出現・538−26=512本文で一致しており、実害はない
（詳細は7節の実測結果、生の出力は
[task-6-measurements.md](../../../.superpowers/sdd/2026-09-06-navigation-slides/task-6-measurements.md)）。

## 2. 何をナビゲーションと呼ぶか

3つの述語で判定する。いずれも実データ608件に当てて誤検出ゼロ・取りこぼしゼロを
確認した。

### 2.1 章扉

次の3つをすべて満たす。「先頭行」は空でない行のうち最初のものを指す。

- 生の行数（空行を含む）が4行以下
- 空でない行が2行以上あり、その先頭行が数字のみ
- 先頭行以外に数字のみの行が無い

空でない行の上限は書かない。生の行数が4行以下なら自動的に4行以下になるためで、
両方書くと同じ制約を2箇所で表すことになる。実データで等価であることを確認した
（どちらも24件）。

生の行数の上限は `モデル就業規則.pdf` の表紙を弾くために要る。

```
'１ \n \n \n \n \n \n \n \nモデル就業規則 \n \n \n \n \n \n \n \n \n令和７年12 月版 '
```

先頭行が全角の `１` で、Python の `str.isdigit()` はこれを真と判定する。本物の
章扉は生の行数が2〜3行、この表紙は19行である。**空行の詰め物があるものは章扉で
はない**という判断でこれを分ける。表紙は版数を尋ねる質問に必要なので落として
はならない。

「それ以外に数字のみの行が無い」は `モデル就業規則.pdf` 34ページのページ番号の
羅列（`17\n18\n19\n10\n…`、765字）を弾く。

### 2.2 目次

先頭の空でない行に「目次」を含み、その行が10字以下。

先頭行の長さは `Claude_Code_法人導入ガイド_スライド.pdf` 13ページ（787字）を弾く。
本文中で目次に言及しているだけで、目次スライドではない。

実データには `－ 目次 ー` と `－ 目次 －` の2種類があり、末尾の記号が資料に
よって異なる。先頭行に含まれるかどうかで見るため、この差は問題にならない。

### 2.3 締め

本文が「ご清聴」で始まる。

### 2.4 外れる向き

3つとも、想定外の入力に対しては**検出しない**側に倒れる。英語資料や別テンプレート
のスライドを入れても、規則が当たらなくなるだけで、本文を誤って捨てる事故は
起きない。

### 2.5 検討して退けた案

**PPTX のレイアウト名で構造的に判別する。** 実測により却下した。対象資料の
全スライドがレイアウト `'DEFAULT'` であり、章扉も目次も本文も区別が付かない。

**長さのしきい値で判定する。** 40字以下の本文断片が実在する
（`。 横展開：コア構成はそのまま` 15字、`。このマインドセッ卜で、RAGの精度は劇的に変わります!` 28字）。
落としてはならないものなので、長さ単独では使えない。

## 3. 設計

### 3.1 置き場所

新規モジュール `ingest/navigation.py` に述語を置く。`ingest/synonyms.py`・
`ingest/conditions.py` と同じ、小さな述語モジュールという既存の型に沿う。

```python
def is_navigation(text: str) -> bool:
    """検索の答えになる中身を持たないスライドか。"""


def drop_navigation(units: list[ParsedUnit]) -> tuple[list[ParsedUnit], list[ParsedUnit]]:
    """残すユニットと、落としたユニットを返す。"""
```

落としたユニットを数ではなく現物で返す。呼び出し側が「何を」落としたか報告
できるようにするためである。数だけでは、誤検出が起きたときに何が消えたのか
追えない。

### 3.2 取り込みへの組み込み

`scripts/ingest_source.py` の取り込みループで、パースとチャンク化の間に挟む。

```python
units = parse(path, caption_image=caption_image)
units, dropped = navigation.drop_navigation(units)      # 追加
chunks = chunk_units(units, source, current_hash, today)
```

ナビゲーション性はスライド単位の性質であり、`ParsedUnit` が自然な単位である。
分割後の断片を見て判断するのは単位がずれる。

`chunk_units()` は変更しない。呼び出し規約が変わらないため既存テストへの波及が
ない。

判定は `unit.text`（パーサーの出力）に対して行う。著作権表記のフッターは既に
パーサーが除いており、第1節で実測した608件はその後の状態なので、規則はその
まま当たる。

### 3.3 VLM との関係

影響しない。章扉・目次スライドが持つ「説明対象の画像」は実測で全スライド0個
だった。装飾は背景画像であり、図形として数えられない。VLM を有効にしても
本文は伸びず、規則は当たり続ける。

### 3.4 報告

`IngestReport` にフィールドを1つ足す。

```python
dropped: dict[str, int] = field(default_factory=dict)   # 資料 → 除外件数
```

進捗表示は `完了: RAGセミナー.pptx（30チャンク、ナビゲーション4件を除外）`、
最後の要約に合計を出す。見えないところで消えることはない。

## 4. 既存DBの扱い

移行スクリプトは要らない。スキーマは変わらず、規則が変わるだけである。

既存DBには26種・38出現が残る。差分取り込みはファイルハッシュが同じものを飛ばす
ので、放っておいても消えない。7本のセミナー資料を入れ直す。

```
python -m scripts.ingest_source --force --only-suffix .pptx
```

共有された本文は、参照が1つでも残っている限り消えない。締めスライドは7資料が
共有しているので、7本すべてを入れ直すまで生き続ける。中途半端に3本だけ入れ
直しても消えない。これは不具合ではなく、`feat/fold-duplicate-chunks` で定めた
畳み込みの規則そのものである。

予測値は **608出現 → 570、本文538種 → 512**。実測して合わなければ、規則か
理解のどちらかが間違っている。

Ollama が必要なため、再取り込みは Colab を起動した状態で行う。

## 5. 壊れ方への備え

ある資料のユニットが**全部**ナビゲーションと判定されたら、何も落とさず警告を
出す。

そのまま落とすと `store.replace_source()` が空のチャンク列を受け取り、その資料が
DBから丸ごと消える。規則が誤爆したときに最も起きてほしくない結果である。

中身のある資料からノイズを取り除くのがこの機能の目的であり、「中身が1つも無い
資料」は規則の誤りである可能性のほうが高い、と判断する。

## 6. テスト

テストの中心は「捕まえるもの」ではなく「捕まえてはいけないもの」に置く。3つの
規則が当たることの確認は容易で、価値があるのは境界のほうである。

新規 `tests/test_navigation.py` に、実データから採った次の3件をそのまま固定する。

| 落としてはいけないもの | どの規則の境界か |
| --- | --- |
| `'１ \n \n … モデル就業規則 … 令和７年12 月版'` | 章扉（生の行数） |
| 787字の PDF 本文中の「目次」への言及 | 目次（先頭行の長さ） |
| `'17\n18\n19\n10\n…'` ページ番号の羅列 | 章扉（数字のみの行の連続） |

規則を緩めるとこれらが落ち、テストが赤くなる。ガードが働いていることは、これで
初めて確かめられる。

`tests/test_ingest_source.py` に2件足す。

- 除外件数が `IngestReport` に載ること
- 全ユニットがナビゲーションと判定された資料で、何も落とさないこと（第5節）

## 7. 成功の判定

設計の段階で「直る」とは書かない。`feat/fold-duplicate-chunks` では、畳み込みが
主張どおりの効果を出した（10位→4位）にもかかわらず回帰ケースは NG のまま
だった。予測と実測を分ける。

予測は、回帰ケースの上位3件が現在すべてナビゲーションなので、それが消えれば
実際の本文が繰り上がる、というものである。ただし RRF とリランカーを通した後の
順位は計算では出せない。

実測するのは3つ。

1. `scripts/check_retrieval.py` で回帰ケースの上位3件
2. **ゲートの距離** — 関連の最大 0.420 / 圏外の最小 0.522 が動くか。落とした
   26種のどれかが境界だった場合は動く
3. **BM25 の絶対値** — 索引が538→512になり idf と平均文書長がまた変わる

結果が NG なら NG と書く。直ったことにはしない。

### 実測結果（2026-09-07）

生の出力の全文は
[task-6-measurements.md](../../../.superpowers/sdd/2026-09-06-navigation-slides/task-6-measurements.md)
を参照。ここには3項目の結論だけ書く。

1. **回帰ケース: OK になった。** `feat/fold-duplicate-chunks` 時点では
   「ファインチューニングについて教えてほしい」の上位3件が章扉・章扉・目次で
   全滅していた。今回、7本のセミナー資料を入れ直した後は上位3件すべてが
   中身のある本文（CNN画像認識セミナー スライド25 ほか、生成AI活用セミナー
   スライド11、スライド34）に置き換わった。「ファインチューニング」単独の
   質問も同様に OK。

2. **ゲートの距離は動いた。** 関連の最大距離 0.420 → **0.455**、圏外の最小距離
   0.522 → **0.545**。落とした26種のうちいくつかが両側でそれぞれ最も近い
   一致だったためである。しきい値0.50を挟んだ分離は保たれている
   （0.455 ≤ 0.5 < 0.545）。余白は0.102→0.090とわずかに狭くなった。

3. **BM25の絶対値は大小が逆転した。** 2026-08-16・約460チャンク時点の実測では
   圏外の長い質問が29.87、関連の短い質問が35.93で関連側が上だった。索引が
   512件になった今回は、圏外の最大BM25が **30.46**、関連の最小BM25が
   **18.96** で、圏外側が上回った。BM25に床（フロア）を設けない判断
   （`ingest/retrieval.py`）は、この逆転によって以前より強く裏づけられた。

## 8. 範囲外

**表紙・講師プロフィール・セミナーの目的のスライド**（スライド1〜3）は落とさ
ない。実測したところ、どれも質問に答えられる中身を持つ。表紙は資料の題名と
日付、講師プロフィールは「講師は誰か」、目的スライドは「この資料は何を扱うか」
に答える。

**検索側での順位調整**は行わない。取り込み時に落とす方針を採ったため、
`ingest/retrieval.py` は変更しない。

**規則の設定ファイル化**は行わない。規則はコードに定数として置く。設定に出す
なら検証とデフォルト値の管理が要るが、それに見合う要求がまだ無い。
