# VS CodeからColabのgpt-oss:20bを使うコーディング環境の設計案

作成日: 2026-09-06

状態: 2026-09-06にユーザーが「Colab接続済。計画通り進めてほしい」と承認。実装とバックエンド受け入れ検証を完了。

## 1. 目的と操作画面

WindowsのVS Codeで `local_llm` を開き、Codex拡張機能のサイドバーから日本語で開発を依頼できるようにする。モデルはColabのL4上のOllamaが提供する `gpt-oss:20b` とし、ファイルの読み書き、コマンド実行、テストはWindows側で行う。

「VS Code内で操作したい」という希望を、サイドバーのチャットを使う意味として設計する。Superpowersの設計・実装計画・TDD・デバッグ・検証のスキルをこの環境でも利用する。

モデルへ渡すコード、指示、ツール結果はColabへ送られる。Colab切断中は新しい推論を実行できない。

## 2. 調査で確認した事実

- VS CodeのCodex拡張 `openai.chatgpt` はインストール済み。バージョンは `26.901.22334`、同梱Codexは `0.153.0`。
- PATH上のCodex CLIは `0.139.0`。拡張の検証には同梱版を使い、両者の挙動を同一と扱わない。
- `.env` のColab接続先へ認証付きで `/api/version` と `/api/ps` を照会し、HTTP 200を確認。Ollamaは `0.33.3`、照会時のロード済みモデルは0件。
- `/api/show` で `gpt-oss:20b` の存在を確認。量子化はMXFP4、機能は `completion`、`tools`、`thinking`。モデル情報上の最大コンテキストは131072だが、実際に確保されるコンテキスト長は未測定。
- 既存の `colab-oss` プロバイダーはResponses APIと `X-API-Key` を設定済み。ただし保存済みURLが現在の `.env` と一致していない。
- Superpowers 6.3.0はCodexのプラグインキャッシュに存在し、14個のスキルを含む。
- 公式資料ではCodex IDE拡張はプラグインに未対応。一方、単体スキルには対応するため、IDEではスキルとして配置する。

接続成功とモデルの機能表示は、エージェントによる編集・テストの成功を意味しない。後者は受け入れ検証で確認する。

## 3. 構成の選択

### 案A: Colab用のVS Code実行環境を分ける（推奨）

専用のVS CodeユーザーデータディレクトリとCodex設定ディレクトリを用意する。起動補助が `.env` を読み、Colab接続設定を生成してVS Codeを開く。日常の操作はそのウィンドウのCodexサイドバーで行う。

Colab用の接続先、モデル、認証、コンテキスト設定をひとまとまりで管理できる。追加の起動補助と実行時ディレクトリが必要になる。

### 案B: 共通のCodex設定をColab用に切り替える

通常のVS Codeから使えるため初期構成は小さい。同じCodex設定を読む他のアプリやCLIにもモデル変更が及ぶため、切り替えと復元の運用が必要になる。

以下は案Aを採用する場合の設計。

## 4. コンポーネントとデータの流れ

1. 起動補助がプロジェクトの `.env` を読み、URL・APIキー・対象モデルを検証する。
2. Colab専用のCodex設定を生成し、起動するプロセスに設定ディレクトリと認証用環境変数を渡す。
3. 専用ユーザーデータディレクトリでVS Codeを起動し、既存のCodex拡張を利用する。
4. Codexは `gpt-oss:20b` を指定し、既存ngrokトンネルと認証プロキシ経由で `/v1/responses` に接続する。
5. モデルのツール要求をWindows上のCodexが実行し、その結果を次の推論へ返す。

VS Codeの既存プロセスが新しい環境変数を引き継ぐとは仮定しない。専用インスタンスの起動と、URL・APIキー更新後の再起動手順を用意する。ユーザーの作業中ウィンドウを自動終了しない。

実行時の保存先は `%LOCALAPPDATA%/local-llm/coding-agent/` とし、`codex/` にCodex設定、`vscode-user-data/` にVS Codeのユーザーデータ、`superpowers/6.3.0/` にスキルの参照元を配置する。生成物はGitへ追加しない。APIキーは設定テンプレートやコマンド引数に埋め込まず、環境変数経由で渡す。接続診断もAPIキーやngrok URLを表示しない。

## 5. Superpowers

インストール済み6.3.0から、ライセンスと参照ファイルを含む構成を保ったローカルコピーを用意する。コピー内の各スキルを、プロジェクトの `.agents/skills` 直下へ個別のディレクトリジャンクションとして配置する。Codexが各 `SKILL.md` を直接検出できる構造にし、IDE上でのスキル検出と相対参照を検証する。プラグインの有効フラグだけでIDEへ読み込まれるとは扱わない。

この配置はプロジェクト単位のため、同じリポジトリで動く別のCodexセッションにもスキルが見える可能性がある。既存の同名ディレクトリや、想定外の参照先を持つジャンクションがある場合は上書きせず、競合として報告する。

まず `using-superpowers`、`brainstorming`、`writing-plans`、`test-driven-development`、`systematic-debugging`、`verification-before-completion` の呼び出しを確認する。初期の受け入れ範囲は1エージェントの編集・検証とし、複数エージェントの並列推論は別の測定課題にする。

## 6. Colabとメモリ

既存の認証プロキシとモデルを使う。Ollama公式がコーディング用途に推奨する64k程度を初期候補とし、Codexのコンテキスト設定とOllamaが確保する長さを合わせる。

モデルを実際にロードした状態でコンテキスト長、GPUメモリ、CPUへのオフロード、応答時間を記録する。64kでGPUに収まると事前には断定しない。収まらない場合は32kを測定し、処理できるタスクと会話の長さへの影響を記録する。

コーディング検証中はVLMやRAG取り込みとの同時実行を避けて測定条件をそろえる。Colabノートブックには起動設定と確認手順を反映する。推論失敗時に別モデルや別サービスへ自動で切り替えない。

## 7. 変更対象

- `scripts/` にColab用VS Codeのセットアップ・接続診断・起動補助を追加。
- `infra/` に秘密情報を含まない設定テンプレートを追加。
- `.agents/skills` にSuperpowersを検出させる配置を追加。
- `colab/run_ollama_server.ipynb` にコンテキストとGPU使用状況の確認手順を反映。
- `.gitignore` に生成物の除外を追加。
- `tests/` に起動補助と設定生成の振る舞いのテストを追加。
- `README.md` に起動、再接続、スキル呼び出し、検証方法を追加。

生成先は環境変数から絶対パスに解決して検証する。生成物に管理用マーカーを付け、初回は既存の未管理ファイルを上書きしない。再実行では本機能が管理する接続設定のみを更新する。

## 8. エラー処理と検証

自動テストでは `.env` 未設定、不正URL、401、Colab停止、タイムアウト、モデル未導入、空白・日本語を含むパス、既存設定との衝突を扱う。外部APIはテスト用応答に置き換え、ユニットテストでColabの稼働を要求しない。

実機では以下を別々に確認する。

1. 接続先・モデル・実際のコンテキスト設定が意図どおりである。
2. Responses APIのストリーミングとツール呼び出し、ツール結果を返す次の推論が完了する。
3. Codex拡張のサイドバーから、検証用フォルダの小さなPythonコードを読み、修正し、テストを実行できる。
4. Superpowersの主要スキルを検出し、設計から検証までの操作例を実行できる。
5. 認証失敗・接続切断時に、原因が分かるエラーとなる。変更済みファイルは利用者が確認できる。

同梱Codexによるプロトコル検証が通っても、VS Code画面の確認が残る場合はその事実を区別して報告する。モデルが20Bであることから、長時間の自律開発や複雑な変更の成功までは保証範囲に含めない。

2026-09-06の実測では、64kコンテキスト時に `context_length=65536`、`size=size_vram=12,971,640,094` バイトとなり、L4へ全量配置できた。Responses APIの関数往復も完了した。VS Code同梱Codex 0.153.0のバックエンドでは、`using-superpowers`の読取、Pythonファイルの編集、指定pytestの `1 passed` まで確認した。Ollamaはfreeform `apply_patch`ツール形式に対応しないため、専用モデルカタログでは公開せずPowerShell編集を使う。
