# コーディング対応ライブラリ

チャット画面のサイドバーで「検索対象」を **技術ドキュメント** に切り替えると、
取り込んだ公式ドキュメントを根拠にコード例・Markdown例・Mermaid を答える。
モデル（`gpt-oss:20b`）の学習時点の知識ではなく、取り込んだ記法で答えさせるための
仕組みである。設計の経緯は
[2026-09-12-latest-docs-ingestion-design.md](superpowers/specs/2026-09-12-latest-docs-ingestion-design.md)
にある。

対象の一覧は `docs_sources.toml` が管理する。本書はその中身と、いま実際にDBへ
入っているものを記録する。**数値はすべて実測であり、測っていないものは
「未測定」と書いてある。**

## 2. 取り込み待ち

**現在なし。** `docs_sources.toml` の6件はすべて `docs_store.sqlite3` に反映済み
である。反映には Ollama への接続（埋め込み）が要るので、追加したときはこの節に
「未取り込み」として残し、埋め込みを走らせてから1節へ移すこと。

実測した所要時間は2回分ある（いずれも NVIDIA L4、ngrok 経由）。

| 日付 | 対象 | チャンク | 所要 |
|---|---|---|---|
| 2026-09-12 | streamlit / huggingface_hub / ollama / pymupdf ほか | 11,993 | 724秒 |
| 2026-09-13 | langchain-text-splitters / mcp | 19,382 | 1,532秒 |

差分取り込みは効いている。2回目は6ファイル中4ファイルが「変更なし」でスキップ
され、新しい2件だけが処理された。

## 4. 実測された品質と使い方

### 日本語で質問してよい

質問は内部で英語の検索クエリに訳してから検索する（`ingest/query_translation.py`）。
**回答は元の日本語の質問から生成する**ので、訳が外れても回答が壊れることはなく、
検索の精度が落ちるだけである。

この仕組みが要る理由は実測にある。取り込んだ資料は英語だが、検索の仕組み
（文字bigramのBM25、日本語で調整したしきい値）は社内資料向けに作られているため、
日本語のまま検索すると外す。

| 質問 | 訳された検索クエリ | Reranker | 答えたAPI |
|---|---|---|---|
| Streamlitのキャッシュはどう書く？ | `Streamlit st.cache_data usage` | 0.06 → **5.68** | `st.cache_data` / `st.cache_resource` |
| Streamlitでモーダルダイアログを出す書き方を教えて | `Streamlit modal dialog st.dialog example` | 3.40 | `st.dialog`（現行シグネチャ） |
| Streamlitでマーメイドの図を描くには | `Streamlit Mermaid diagram ...` | 0.77 | `st.mermaid_chart` |

翻訳を入れる前は、1行目の質問が CLI の `streamlit cache clear` を引き、モデルは
（渡された根拠に照らして正しく）「ドキュメントには記述がありません」と答えていた。

### API 名を書くと強い

同じ内容でも、API 名を含めた方が検索が当たる。実測（2026-09-12、Streamlit）:

- `st.cache_data`（API名）→ Reranker **7.02**
- `How do I cache data in Streamlit?`（英語の文）→ **5.73**
- `Streamlitのキャッシュはどう書く？`（日本語の文）→ **0.06**

分かっている API 名があれば質問に入れるとよい。翻訳を挟んでも同じで、上の
langchain の例のように、訳がクラス名まで届かないと外す。

### langchain と mcp（2026-09-13 追加分）

翻訳・ベクトル検索・BM25・リランカーを通しで実測した（`gpt-oss:20b`、
NVIDIA L4、ngrok 経由）。

| 質問 | 訳された検索クエリ | Reranker | 引いた内容 |
|---|---|---|---|
| MCPのstdioトランスポートでクライアントを作るには | `MCP stdio transport create client` | **4.62** | MCP クライアントの作り方、参加者の構成 |
| MCPサーバーでツールを定義する書き方 | `MCP server tool definition` | **3.33** | MCP サーバーの役割とツール定義 |
| LangGraphでグラフのノードとエッジを定義するには | `LangGraph define graph nodes edges` | **1.94** | `Define a new graph` の例、`graph.compile()` |
| LangChainでテキストを分割する書き方を教えて | `LangChain TextSplitter usage` | **-0.09** | `pip install` の行（**外した**） |

**最後の1件は外している。** 引いたのはインストールコマンドで、分割のコードでは
ない。同じ内容でも API 名を含む `LangChain RecursiveCharacterTextSplitter split
text example` で引くと、`PyMuPDFLoader` と分割の実例が出る（BM25とリランカーのみ
で1.54）。訳が `TextSplitter` までしか出せず、`RecursiveCharacterTextSplitter`
という実際のクラス名に届かなかったことが原因である。

これは下の「API 名を書くと強い」の2つ目の実例になっている。**翻訳はクラス名まで
は当てられないことがある。** 分かっている API 名は質問に書いた方がよい。

### 弱いところ

- **Mermaid の質問が最も余裕が少ない。** 上表で Reranker 0.77 と、他の質問の
  1/5 以下である。正答はしたが、外れやすい部類に入る。
- **pymupdf は資料そのものが薄い。** 概要止まりで API リファレンスを含まない。
- **本文に出典は出ない。** 出典は回答の下の「参考にした情報」を開くと出る。
  実測10回の回答すべてでファイル名は本文に出なかった（`gpt-oss:20b` のみで確認）。

## 5. ライブラリを追加する

`docs_sources.toml` に足して、取得と取り込みを走らせる。

```bash
python -m scripts.fetch_docs
python -m scripts.ingest_source --source-dir docs_source \
    --db docs_store.sqlite3 --keep-code-blocks
```

追加するときの注意が2つある。

**`llms.txt` ではなく `llms-full.txt` の URL を書くこと。** `llms.txt` は各ページへの
リンクの目次であって本文ではない（実測 2026-09-12: `docs.streamlit.io/llms.txt` は
66,927バイトあるがコードフェンスは**0個**）。目次を取り込むと、検索は当たるのに
答えが書けないという診断しにくい状態になる。

**ドキュメントのドメインはパッケージ名から推測できない。** 実例:

- `mcp` → `modelcontextprotocol.io`（PyPI 名と無関係）
- `langchain-text-splitters` → `docs.langchain.com`（`python.langchain.com` は HTML を返す）
- `huggingface_hub` → `huggingface.co/docs/huggingface_hub/`（サブパス）

URL を間違えても、サーバーが 200 で HTML を返すことがある。`fetch_docs.py` は
本文の先頭と `Content-Type` の両方を見て HTML を弾き、`NotDocumentationError` を
投げて1件の失敗として報告する（他のライブラリの取得は続く）。本文中に HTML の例が
出てくる正しい資料は捨てない（先頭だけで判定しているため）。

この歯止めは実害があって入れた。`python.langchain.com/llms-full.txt` は 404 では
なく、ドキュメントサイトの HTML を **200 で** 返す（実測 2026-09-13）。状態コード
しか見ていなかったため素通りし、HTML・CSS・JavaScript が **1,531チャンク**
（当時のコーパス11,993件の12.8%）DB に入っていた。汚染分は削除済みである。
この失敗は静かで診断が遠い。取り込みは成功と表示され、検索も当たり、ただ答えが
書けないノイズが混ざるだけだからである。

## 6. 更新

取得は内容の SHA-256 を前回と比べ、変わったものだけ書き出す。変わっていなければ
「変更なし」と報告してファイルを書き換えないので、取り込みも走らない。

定期実行はしない。人が `scripts/fetch_docs.py` を起動したときだけ外部へ通信する
（`AGENTS.md` の「外部ドキュメントの参照」参照）。

`docs_source/` と `docs_store.sqlite3` は `.gitignore` 済みである。
`source/` と `vector_store.sqlite3` と同じく、いつでも取り直せるためである。
追跡するのは設定ファイル `docs_sources.toml` だけ。
