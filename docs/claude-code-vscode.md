# クライアントPCで Claude Code を VS Code 拡張として使う

各開発者の PC に Claude Code の VS Code 拡張を入れ、社内資料の MCP サーバへ繋ぎ、
`CLAUDE.md` で「いつ社内資料を引くか」を教えるまでの手順である。

[mcp-server-network.md](mcp-server-network.md) の「クライアント側の設定」は Codex 版
（`~/.codex/config.toml` と `~/.codex/AGENTS.md`）である。本書はその Claude Code 版
にあたる。サーバ機の構築手順は本書の範囲外で、上記の文書にある。

**Claude Code は `AGENTS.md` を読まない。読むのは `CLAUDE.md` である。** 本リポジトリの
[AGENTS.md](../AGENTS.md) をそのまま置いても効かない。第4章で対処する。

## 前提

- サーバ機で `rag_mcp_server` が `http://<サーバIP>:8080/mcp` で動いている
  （[mcp-server-network.md](mcp-server-network.md) の手順が完了している）
- VS Code 1.94.0 以降
- Claude の有料プラン（Pro / Max / Team / Enterprise）または Claude Console の
  アカウント。**API キーは不要である**

クライアント側に Python も Ollama も資料も要らない。埋め込み計算もリランクも
サーバ機で行う。

## 1. 拡張機能を入れる

VS Code で `Ctrl+Shift+X` を押して拡張機能ビューを開き、「Claude Code」で検索して
**Install** する。発行元は Anthropic である。

インストール後に表示されない場合は、コマンドパレット（`Ctrl+Shift+P`）から
**Developer: Reload Window** を実行する。

**拡張機能は `claude` コマンドを PATH に追加しない。** 拡張機能はチャットパネル用の
CLI を内部に同梱しているだけである。統合ターミナルで `claude` を叩きたい場合は、
CLI を別途インストールする。本書の第3章は統合ターミナルで `claude mcp add` を使う
ので、CLI が要る。

```powershell
# CLI を入れる（未導入の場合。PowerShell で実行する）
irm https://claude.ai/install.ps1 | iex

claude --version
claude doctor
```

npm 版（`npm install -g @anthropic-ai/claude-code`）もあるが、公式が推している
ネイティブインストーラは自動更新が効く。npm 版は Node.js 22 以降が要る。

[Git for Windows](https://git-scm.com/downloads/win) を入れておくと Claude Code が
Bash ツールを使える。無い場合は PowerShell ツールで代替される。本リポジトリの
手順は PowerShell で書いてあるので、どちらでも支障はない。

## 2. サインインする

エディタ右上のスパークアイコン、または左のアクティビティバーのスパークアイコンから
パネルを開く。初回はサインイン画面が出るので、**Sign in** を押してブラウザで承認する。

`ANTHROPIC_API_KEY` をシェルに設定しているのにサインインを求められる場合は、
VS Code がシェルの環境変数を継承していない。ターミナルから `code .` で起動し直すか、
Claude アカウントでサインインする。

## 3. 社内資料の MCP サーバへ繋ぐ

統合ターミナル（`` Ctrl+` ``）で登録する。

```powershell
claude mcp add --transport http --scope user local_docs http://192.168.1.50:8080/mcp
```

IP はサーバ機のものに置き換える。**末尾の `/mcp` を省かないこと。** 省くと 404 に
なり、Claude 側からは「サーバが応答しない」としか見えない。

### スコープを選ぶ

`--scope` は3種類あり、既定は `local`（そのリポジトリでだけ、自分だけ）である。

| スコープ | 保存先 | 効く範囲 |
| --- | --- | --- |
| `local`（既定） | `~/.claude.json` のプロジェクト配下 | そのリポジトリだけ |
| `user` | `~/.claude.json` の最上位 | そのPCの全リポジトリ |
| `project` | リポジトリ直下の `.mcp.json` | Git 経由でチーム全員 |

社内資料はリポジトリを問わず引きたいので `--scope user` を推す。`project` は
サーバの IP をリポジトリに固定してしまうため、サーバを引っ越すと全員が壊れる。

### GUI から登録する場合

チャットパネルで `/mcp` と入力するとダイアログが開く。ただし**ダイアログからの追加・
削除は Claude Code v2.1.261 以降**である。それ未満（例：v2.1.227）ではダイアログは
接続状態の確認と有効・無効の切り替えだけで、追加は上のコマンドで行う。

### 登録できたか確かめる

```powershell
claude mcp list
```

`local_docs` が **Connected** で出れば正しい。`Failed` の場合は第6章を見る。

## 4. `CLAUDE.md` を置く

**ここが本題である。** MCP の登録が教えるのは接続先だけで、**どの質問で検索するか**は
エージェントの判断に委ねられる。ツールの説明文は「社内資料を検索し、根拠となる原文を
出典つきで返す」だけで（[rag_mcp_server.py:205](../scripts/rag_mcp_server.py#L205)）、
呼ぶべき条件を含まない。Claude が自分の知識で答えてしまえば、サーバが結果に添える
歯止め（`_FALLBACK` / `_CAUTION`）は一度も読まれずに終わる。

### 置き場所と読み込み順

読み込みは広い順で、後に読んだものほど近い指示として扱われる。

| 種別 | 置き場所（Windows） | 共有範囲 |
| --- | --- | --- |
| 管理ポリシー | `C:\Program Files\ClaudeCode\CLAUDE.md` | 組織の全員（個人設定で除外できない） |
| ユーザー | `C:\Users\<ユーザー名>\.claude\CLAUDE.md` | 自分の全プロジェクト |
| プロジェクト | リポジトリ直下の `CLAUDE.md` または `.claude\CLAUDE.md` | Git 経由でチーム |
| ローカル | リポジトリ直下の `CLAUDE.local.md` | 自分・そのリポジトリだけ（要 gitignore） |

作業ディレクトリとその**上位すべて**の階層から読まれる。下位ディレクトリのものは、
Claude がそのディレクトリのファイルを読んだときに遅れて読まれる。

### 資料を引くだけの利用者：`~/.claude/CLAUDE.md`

ここに置いたものはリポジトリを問わず読まれるので、開発者が別のリポジトリで作業して
いても効く。**既にファイルがある場合は追記する（上書きしない）。**

```powershell
notepad $env:USERPROFILE\.claude\CLAUDE.md
```

本リポジトリの [AGENTS.md](../AGENTS.md) から「社内資料の参照」節をそのまま貼る。

```markdown
## 社内資料の参照

- 社内資料・規程・議事録・会議録に関する質問は、推測せず `search_documents` で
  検索し、返された出典を明記して回答すること。
- 検索結果が質問と無関係な場合は、それを根拠に使わないこと。距離が閾値内である
  ことは関連性を保証しない。
- 検索が0件だった場合、および結果が無関係だった場合は、再検索やウェブ検索で
  補おうとしないこと。一般的な知識で答えられる質問なら、社内資料に基づかない
  一般的な回答である旨を断ったうえで通常どおり回答してよい。社内固有の事項
  （規程・議事録・社内の決定・組織固有の運用）だけは推測せず、社内資料からは
  確認できない旨を答えること。
- 資料に書かれていない主体（「弊社が」等）を補わないこと。
```

**冒頭の開発ガイドライン部分は貼らないこと。** superpowers スキル・PowerShell・
仮想環境の取り決めであり、資料を引くだけの利用者には無関係である。

context7 も併用するなら「外部ドキュメントの参照」節も貼る。社内固有の語を context7
のクエリに含めない、という制約はここにしか無い。context7 は社外のサービスであり、
MCP サーバを経由しないため、この一行を落とすと社内の語がそのまま外へ出る。

### 本リポジトリで開発する人：`CLAUDE.md` から `AGENTS.md` を読ませる

Claude Code は `AGENTS.md` を読まない。リポジトリ直下に `CLAUDE.md` を作り、
`@` インポートで既存の `AGENTS.md` を取り込む。二重管理にならない。

```markdown
@AGENTS.md

## Claude Code 固有

- 記載の PowerShell コマンドは統合ターミナルでそのまま使える。
```

シンボリックリンクでも同じことができるが、Windows では管理者権限か開発者モードが
要るので、インポートを使う。

インポートは相対パスでも絶対パスでも書け、インポート先がさらにインポートできる
（最大4段）。バッククォートで囲んだ `` `@AGENTS.md` `` はインポートされずただの文字列
として扱われる。

### 組織へ一括配布する場合

管理ポリシーの位置（`C:\Program Files\ClaudeCode\CLAUDE.md`）に置くと、そのPCの
全セッション・全リポジトリで読まれ、利用者側の設定では除外できない。MDM や
グループポリシーで配る。`managed-settings.json` の `claudeMd` キーに本文を直接
書く方法もある。

### 書き方の注意

- **200行以内に収める。** 長いほどコンテキストを食い、指示の遵守率が下がる
- 「適切にフォーマットする」ではなく「インデントは半角2」のように、検証できる
  具体性で書く
- 複数の `CLAUDE.md` で矛盾する指示があると、Claude はどちらかを恣意的に選ぶ。
  定期的に見直す
- `CLAUDE.md` はコンテキストであって強制ではない。**必ず実行させたい処理は
  フック**（`PreToolUse` 等）で書く

### `CLAUDE.md` が無いと何が壊れるか

0件時・無関係時の出口（一般知識でなら答えてよい、社内固有の事項は推測しない）は
サーバが検索結果に毎回添えるので、`CLAUDE.md` が無くても効く。二重になっているのは
意図的である。

`CLAUDE.md` にしか無いのは次の2つで、どちらもサーバからは手が届かない。

- そもそも `search_documents` を呼ぶ、という判断。呼ばれなければサーバの文言は
  存在しないのと同じである
- 社内固有の情報を context7 のクエリ文に含めない、という制約

## 5. 動作確認

新しい会話を開いて、次の順に確かめる。

1. `/context` を実行し、**Memory files** に置いた `CLAUDE.md` が出ることを見る。
   ここに出ないファイルは Claude から見えていない
2. `/mcp` で `local_docs` が **Connected** であることを見る
3. 「社内資料で〜を調べて」と頼み、出典つきの原文が返ることを見る
4. 資料と無縁の質問（ライブラリの使い方など）も投げる。**0件のときは検索を打ち切り、
   一般知識で答える**のが正しい挙動である。そのとき回答には「社内資料に基づかない
   一般的な回答である」旨が添えられる
5. 「就業規則の有給日数」のような社内固有の質問を検索が外したときに、それらしい
   数値が創作されないことを確かめる

DB が空のままだと「ベクトルDBが空です。取り込みが未実行の可能性があります」と返る。
「見つかりませんでした」とは別の文言なので、資料に無いのか取り込みを忘れているのかは
区別できる。

`/memory` を使うと `CLAUDE.md` の一覧が出て、選んだファイルをそのまま編集できる。
まだ存在しないファイルを選ぶと新規作成される。

## 6. うまくいかないとき

| 症状 | 原因と対処 |
| --- | --- |
| `/mcp` で `Failed` | URL の末尾 `/mcp` の欠落、サーバ機のファイアウォール、サーバ未起動。サーバ機で `Invoke-WebRequest` による疎通確認（[mcp-server-network.md](mcp-server-network.md)）を先に通す |
| `CLAUDE.md` を書いたのに従わない | `/context` の **Memory files** に出ているか確認する。出ていなければ置き場所が読み込み対象外である。出ているのに従わない場合は、指示が曖昧か他のファイルと矛盾している |
| 社内資料の質問なのに検索しない | `~/.claude/CLAUDE.md` の「社内資料の参照」節が入っていない。第4章 |
| MCP を登録したのに会話に出ない | 登録は**その後に開始した会話**から効く。会話を開き直す |
| `claude` コマンドが無い | 拡張機能は PATH に追加しない。CLI を別途入れる（第1章） |
| サインインを求め続ける | **Developer: Reload Window**。それでも直らなければ `code .` で起動し直す |

拡張機能のログはコマンドパレットの **Claude Code: Show Logs** で見られる。

## 制限

- **同時アクセスは順番待ちになる。** サーバ側で検索を直列化してある。検索1回は
  およそ 3.6 秒、サーバ起動後の初回だけ 8.2 秒である。3人が同時に叩けば最後の1人は
  およそ 11 秒待つ（実測条件は [mcp-server-network.md](mcp-server-network.md)）
- 通信は平文 HTTP で認証が無い。到達できる範囲をファイアウォールで絞ることが唯一の
  境界である。この構成が守るもの・守らないものは
  [mcp-server-network.md](mcp-server-network.md) の表を必ず読むこと
- `CLAUDE.md` は強制ではない。従わせたい処理が確実に走る必要があるならフックで書く
- 拡張機能のスラッシュコマンドは CLI の全部ではない。`!` によるシェル実行や
  タブ補完は CLI 専用である。必要なときは統合ターミナルで `claude` を使う
