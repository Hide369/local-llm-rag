# 処理箇所マップ

RAGパイプラインの主要処理が、どのファイルのどこで行われているかの索引。
行番号は 2026-08-30 時点（master: 938fc2f）のもの。

対象は本番コード（`ingest/`, `scripts/`, `rag_chat_app.py`）。
`udemy1.py`〜`udemy3.py` は教材用の旧実装で、本番パイプラインとは別系統（別コレクション `local_docs`）だが、比較のため末尾に併記する。

## 全体の流れ

```
source/ の資料
  └ ingest/parsers/         形式ごとに解析 → ParsedUnit（OCR / VLM はここで発動）
      └ ingest/chunker.py   チャンク分割
          └ ingest/embedder.py  ベクトル化（Ollama bge-m3）
              └ ingest/store.py ChromaDB へ格納
                                    │
質問 ─ ingest/retrieval.py ─┬ ベクトル検索（ChromaDB）
                            ├ BM25検索（ingest/lexical.py）
                            └ RRF で融合 → 上位4件 → ingest/prompting.py → LLM
```

## 3. Reranker でランキングしている箇所

**該当なし。現在のコードに Reranker（クロスエンコーダによる再ランキング）は実装されていない。**

- [2026-08-15-hybrid-retrieval-design.md:125](superpowers/specs/2026-08-15-hybrid-retrieval-design.md#L125) に「**リランカー（bge-reranker-v2-m3）の導入**: 効果は見込めるが、モデルの…」として *採用しなかった案* として記載があるのみ。
- 依存パッケージにも `sentence-transformers` / `FlagEmbedding` 等のリランカー用ライブラリは入っていない。

### 代わりに行っている並べ替え

再ランキングに相当する処理は、RRF（Reciprocal Rank Fusion）による順位融合が担っている。

| 箇所 | 内容 |
|---|---|
| [retrieval.py:37](../ingest/retrieval.py#L37) | `RRF_K = 60`（順位の逆数を足すときの緩和定数） |
| [retrieval.py:190-194](../ingest/retrieval.py#L190-L194) | `1/(RRF_K + rank)` をベクトル側・BM25側それぞれから加算 |
| [retrieval.py:211-218](../ingest/retrieval.py#L211-L218) | 最終ソート。RRFスコア降順 → ベクトル距離昇順 → BM25スコア降順 → チャンクID（同点でも並びを決定的にするため） |
| [retrieval.py:219](../ingest/retrieval.py#L219) | 上位 `SEARCH_RESULT_COUNT = 4` 件を返す |
| [lexical.py:111](../ingest/lexical.py#L111) | BM25側のランキング（スコア降順、同点はID順） |

> コード内コメント（[retrieval.py:133-135](../ingest/retrieval.py#L133-L135)）にある通り、RRFスコアは順位のみに依存するため**採否の判定には使えず**、採否はベクトル距離のしきい値が担っている。
